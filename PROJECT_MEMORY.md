## 1. Project Overview

**TutorGali** is a Django web application that connects students with tutors across India.

### Core User Flows
1. **Student** registers → searches tutors by grade/subject/location/mode → sends booking request → views accepted bookings → leaves a review
2. **Tutor** registers → completes onboarding profile → uploads verification documents → admin approves → appears in search → accepts/rejects booking requests → optionally buys a subscription to unlock unlimited student contact details
3. **Admin** (custom panel at `/admin-panel/`) manages tutor verification, views all bookings, reviews, subscriptions, and revenue

### Business Rules
- Tutors get **5 free contact views** (accepting booking requests). After that, they must buy a subscription.
- Only **approved + profile_completed** tutors appear in search results.
- Students can only leave a review if the tutor has **accepted** their booking request.
- One booking request per student-tutor pair (unique_together constraint; old one is deleted and replaced on re-request).
- One review per student-tutor pair (update_or_create used).

## 7. OTP Flow (Fast2SMS)

1. User enters mobile number → clicks "Send OTP"
2. AJAX POST → `send_otp` view
3. **60-second cooldown check** — blocks resend if < 60s since last send
4. 6-digit OTP generated
5. POST to `https://www.fast2sms.com/dev/bulkV2` with `route=otp`
6. **If Fast2SMS succeeds:** OTP stored in session, success response sent
7. **If Fast2SMS fails (dev fallback):** OTP logged to Django console via `logger.warning('[DEV OTP] ...')`, still stored in session, success response with `[DEV]` message
8. User enters OTP → AJAX POST → `verify_otp` view
9. Checks: max 3 attempts, 10-min expiry, mobile match, OTP match
10. On success: `otp_verified = True` in session, submit button enabled
11. On form submit: `register` view checks `otp_verified == True` (Gate 1) + mobile match (Gate 2)
12. On successful registration: all OTP session keys cleared

**Note on corporate/office networks:** Fast2SMS may be blocked by firewalls (e.g. Zscaler/NPCI). Use mobile hotspot for local testing, or rely on the dev fallback (OTP in console). On the VPS server, Fast2SMS works fine.

## 9. Known Issues / TODO

### Remaining Bugs (from audit — not yet fixed)
- **Admin logout via GET** — CSRF logout attack possible (`admin_panel_logout` has no `@require_POST`)
- **Open redirect via `HTTP_REFERER`** in `create_booking_request` — use `url_has_allowed_host_and_scheme()`
- **Silent deletion of accepted bookings** — re-submitting a booking deletes existing accepted one
- **Free contact counter race condition** — use `F()` + `select_for_update()` for atomic increment
- **Duplicate subscription on Razorpay callback retry** — no idempotency check
- **`zip` iterator bug** in `tutor_onboarding` and `tutor_edit_profile` — use `list(zip(...))` instead of lazy `zip`
- **`save_profile` signal** causes unnecessary DB write on every user save — remove it
- **Staff/superuser with no profile role** → infinite redirect loop to `/login/`
- **`distance_km` GET param** not wrapped in try/except — `float('abc')` raises 500

